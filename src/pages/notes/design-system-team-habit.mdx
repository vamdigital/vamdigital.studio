A component library is useful infrastructure, but it does not become a design system simply because it has buttons, colours, and documentation.

## Agreement creates consistency

The system becomes real when designers and engineers use the same language, review changes together, and know when a pattern should be reused or challenged.

## Documentation records decisions

Storybook is most valuable when it explains intent: what a component is for, which states matter, and what trade-offs shaped it. Examples alone cannot carry that context.

The strongest design systems are maintained through repeated team behaviour, not occasional cleanup projects.
